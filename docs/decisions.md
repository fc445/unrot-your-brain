# unrot-your-brain — decisions.md
(append-only; reconstructed from the existing design doc as of 2026-09-12)

- **2026-09-01 — Rejected network-proxy/gateway capture.** Claude Desktop's third-party gateway mode reroutes traffic rather than tapping it, forcing subscription users onto pay-as-you-go API billing. Kills the "attach without changing your workflow" premise.
- **2026-09-01 — Chose local JSONL transcript parsing as the capture layer.** Claude Code already writes full session transcripts to `~/.claude/projects/<project>/<session-id>.jsonl`, working identically across CLI/VS Code/JetBrains/Desktop and under both subscription and API billing.
- **2026-09-01 — Chose hook-triggered analysis over filesystem polling.** Claude Code's hook system fires on session events and passes the transcript path directly.
- **2026-09-01 — Chose behavioral signal as the primary detection method.** Unexplained term + immediate blind acceptance = flagged gap; a clarifying question = not a gap. Preferred over self-report, which is unreliable (people confirm familiarity with things they don't know).
- **2026-09-01 — Chose "what is it in one line?" as the secondary confirmation check**, not yes/no self-assessment — functions as a real check rather than a survey.
- **2026-09-01 — Set flag budget to ~1–2 surfaced gaps per session.** Precision over recall; this is what determines whether people keep using it past day three.
- **2026-09-01 — Deferred the prerequisite graph and curriculum engine.** Needs real gap data to design against; not needed for v1.
- **2026-09-01 — Chose MCP server + `/unrot` slash command as the delivery surface.** Pull-based, no injected text, no interruption — over a dashboard or digest.

## 2026-09-16 — PRD drafting session

### Positioning and scope

- **2026-09-16 — Positioned against knowledge gaps, not AI fluency.** Existing OSS tools (claude-insight, skill-tree, claude-session-analyzer) and Anthropic's own scorecard all measure *collaboration style* — how well someone delegates, describes, iterates. unrot targets knowledge gaps in daily workflow that AI silently assumes the user already has. Different axis; describe it that way to avoid reading as a weaker clone of the fluency category.
- **2026-09-16 — REVERSED the MCP + `/unrot` delivery decision (2026-09-01).** unrot is a **silent, capture-only** integration to Claude Code with no in-agent interaction of any kind. All interaction happens in a separate product surface with its own UI and backend. The agent is a data source, not an interface.
- **2026-09-16 — Chose v1 = walking skeleton over detector-first.** A thin slice through every layer (capture → detect → store → manual input → surface → learn), deliberately crude but end-to-end runnable. "Is this loop worth having" is as risky an unknown as "does the detector work," and only an end-to-end version tests both. **Supersedes `brief.md`'s "smallest version = analyzer plus validation only."**
- **2026-09-16 — Reduced hand-labelling from ~10 sessions to 2–3.** Kept as a sanity check specifically so a disappointing week of self-use can be diagnosed as bad detection vs. bad concept.
- **2026-09-16 — Chose zero-shot detection for v1.** Semantic-similarity is spike-worthy but non-blocking (PR-13).
- **2026-09-16 — Chose not to over-formalise module interfaces.** Four modules (parser / detector / store / delivery), one person; a shared dataclass shape is sufficient.

### Structural decisions (S1–S7)

- **2026-09-16 — Established S1–S7 as blocking structural decisions.** No schema and no code until resolved. Each is cheap now and expensive-to-impossible to retrofit once real data accumulates.
- **2026-09-16 — S1: split `concept` from `encounter`.** Concepts are compiled state; encounters are events. One row per concept loses history; two independent rows lose the repetition signal — and repetition across months is plausibly the most valuable signal in the product.
- **2026-09-16 — S5: the store is derived and re-runnable, not a write-once source of truth.** Improving the detector should retroactively improve the whole history, not apply only from that point forward. Requires retaining transcripts, recording which detector version produced each gap, and treating regeneration as a first-class operation. **User judgments (confirms, dismissals, explanations) must survive regeneration** — they are human input, not derived data.
- **2026-09-16 — S4: two-layer storage.** Raw transcripts retained **locally and never synced**; graph events carry an LLM-generated paraphrase plus a pointer (session id + line range) back to the raw. Resolves the S4/S5 tension: re-runnable *and* private. Rationale: Claude Code already writes these transcripts to disk, so retaining them adds no new exposure — **the exposure is the sync, not the storage.** Privacy boundary is the sync line.
- **2026-09-16 — S6 and S7 resolved by the event-log model.** An append-only log is versioned by construction (S6); logs merge without locking (S7).
- **2026-09-16 — S2: collapsed SOLO taxonomy, 3 levels** (isolated / listed / causal), explicitly flagged as changeable later. The boundary that matters is listed → causal: that is where recall separates from comprehension. **The irreversible part is storing the raw text of the user's explanation** as a separate event from its grade, so any future rubric can re-grade the entire history.
- **2026-09-16 — S3 downgraded from blocking to a spike.** Whether the atom is a `term` or a typed `gap` (term / decision / tool-call) needs empirical work and possibly user guidance. Does not block v1 for internal use — build with a term-shaped atom and keep the spike open.

### Storage and ingestion

- **2026-09-16 — Chose an append-only event log compiled to current state.** Gives S5, S6 and S7 largely for free, and gives an LLM the chronological reasoning trail rather than only the end state.
- **2026-09-16 — Chose Postgres over ClickHouse.** ClickHouse targets analytical scans over very large volumes; this workload is small writes and current-state lookups for a single user's graph. Append-only is a convention kept, not a database feature bought.
- **2026-09-16 — Nothing writes to the graph directly.** Every write — automatic ingestion and manual submission alike — passes through an LLM resolution step. Conflicts are therefore prevented at ingestion rather than reconciled at compile; the resolver is the serialisation point and compile stays a dumb fold.
- **2026-09-16 — Resolver judgments are appended as first-class events.** "Merged X into Y because it looked like a misspelling" is a judgment that can be wrong and must be correctable; storing only the outcome leaves nothing to correct against.
- **2026-09-16 — Accepted staleness rather than locking.** The resolver reads latest state, reasons, appends. Worst case is a duplicate concept a later pass merges — and merges are themselves correctable events. Not worth building locking for a single user.
- **2026-09-16 — Parked the general versioned-decision system as a separate later project.** Append-only markdown with explicit `supersedes:` references, compiled to current state. Same mechanism as the event log; building the general version inside unrot would roughly double the project. Plausibly a skill. Hone on unrot's single use case first.

### Graph semantics

- **2026-09-16 — Material is a first-class entity with a many-to-many join to concepts.** An explanation of eventual consistency necessarily covers partitions and quorum. Creates a third node state, **exposed**: named in material the user received, but not confirmed and not unseen.
- **2026-09-16 — Added a `referenced` node state.** A concept named in material but never encountered by the user. Scaffolding for clustering and future edges; never surfaced, never counts toward the flag budget. Validates the S1 split — a concept with zero encounters is valid, a gap requires an encounter.
- **2026-09-16 — Capped graph expansion at depth 1.** A concept enters the graph if named in material the user actually received; it does not then generate its own material, and its neighbours are not pulled in. Expansion is driven by encounters, never by the graph's own contents. Explosion comes from recursion, not from adding.
- **2026-09-16 — Deferred typed edges.** Similarity and clustering stand alone without them. When edges arrive, model them as events with a **free-text `type`, no enum** — structure without an unearned ontology.
- **2026-09-16 — Scoped vector similarity to resolution and clustering, not relationships.** Similarity cannot distinguish *same as* from *opposite of in the same space* (optimistic vs. pessimistic locking embed near-identically), and is symmetric where prerequisites are directional. Use it for ingestion near-duplicate detection and the domain heatmap.
- **2026-09-16 — Chose an LLM-proposes / similarity-verifies ensemble** for future edge work. Both agree → store; LLM proposes but similarity distant → likely hallucinated, drop; similarity close but LLM finds no relationship → clustering only. Precision-over-recall applies to edges more tightly than to flags, since a wrong prerequisite edge actively misroutes learning.
- **2026-09-16 — Store model/grader/detector versions alongside all derived state.** Embeddings, SOLO grades and gap detections are all derived; a silent model upgrade otherwise changes the meaning of history.

### Learning material

- **2026-09-16 — Sourcing/provenance is a P0 quality gate.** The product generates explanations of precisely the things the user cannot evaluate — a hallucinated definition lands on someone who by definition can't catch it, and is then wrong in their head *and* in the graph. Worse than not flagging at all. Grounding and provenance over free generation.
- **2026-09-16 — The user controls material generation at three levels:** whether it happens at all (pure-detector mode must be fully useful), what style within a format, and links-only as a first-class output. Material generation is a pluggable output stage; the gap graph is the product.
- **2026-09-16 — Chose to teach from the user's own code where possible.** Explain the queue in their ingest service, not backpressure in the abstract. A generic explainer is a commodity; an explanation grounded in the user's codebase is the moat.

### Product surfaces

- **2026-09-16 — Chose a domain heatmap over graph visualisation.** A sparse early graph looks pathetic and teaches nothing; gap density by domain over time is honest at low data volume and useful at high.
- **2026-09-16 — Chose to surface knowledge evolving over time.** The event log is already a time series, so per-concept trajectories cost nothing extra. Directly counters the shame-spiral risk: the same data, progress-shaped rather than deficit-shaped. **This is the strongest argument for the event log over a mutable store** — an overwritten row has no trajectory to show. Requires recording non-interaction events (vocabulary production, silent resolution, re-encounters) as densely as explicit ones.
- **2026-09-16 — Named inverted trust as an accepted, monitored risk.** "unrot will catch it" could license more blind acceptance. Mitigating factor: unrot has no write path and changes nothing about what ships, so it cannot be leaned on mechanically. Measure it — a falling clarifying-question rate after onboarding is the signal.

### The inversion

- **2026-09-16 — Adopted agent calibration as the direction of the integration.** unrot tells the agent *how to pitch explanations* — more for concepts the user doesn't know, less for those they do. Not a gap report, not an interface. The agent surfaces nothing about unrot, asks nothing on its behalf, interrupts nothing.
- **2026-09-16 — Ruled out "second brain" positioning.** Saturated and faddish category. Frame as the agent adapting to what you know, not as externalising your mind.
- **2026-09-16 — Reopened the MCP decision, narrowly, for resources only.** MCP exposes tools, prompts and resources; the 2026-09-01 reversal was about not building an *interaction surface*, which still holds for tools and prompts. Resources are a read path. Testable first as a plain generated context file with no MCP at all.

### Commercial

- **2026-09-16 — Parked enterprise/commercial work, with two items flagged as time-sensitive:** the Apache 2.0 licence choice (permits a cloud vendor to run the aggregation layer as a service — revisit before there is anything worth taking), and S4 becoming a procurement requirement rather than a design preference.
- **2026-09-16 — Ruled out individual comprehension scoring as an enterprise product.** A tool that reports individual developer comprehension to managers destroys its own signal: developers game blind acceptance, which is the exact behaviour the detector depends on. Must be architecturally impossible, not a policy promise. Aggregate views (codebase risk map, documentation gaps, onboarding, agent calibration) are both safer and more valuable.

## 2026-09-16 — v1 backlog session

- **2026-09-16 — Chose SQLite for v1, with the schema kept portable to Postgres.** Resolves a contradiction inside the PRD, which said "Postgres, not ClickHouse" in the Storage & Ingestion section and "SQLite is fine" in the v1 Requirements section. v1 is local-only — the remote server is on the "genuinely absent" list — so SQLite matches the surface actually being built. This costs nothing structurally, because **append-only is a convention that's kept, not a database feature that's bought**: avoid SQLite-specific types and the event log ports to Postgres when the remote server lands. Does not reverse the Postgres-over-ClickHouse decision, which still stands for the hosted layer.
- **2026-09-16 — Kept regeneration inside the v1 skeleton rather than deferring it.** S5's re-runnability is what makes every S1–S4 modelling mistake cheap to correct; deferring it means the first time it is needed is the first time it is tried, on history that matters. A command is sufficient — no UI.
- **2026-09-16 — S17: the two v1 learning-material formats are (1) textual explanation with sources and (2) sources only / discovered material.** Chosen so the two exercise genuinely different paths rather than two shades of prose: format 1 generates and must cite, format 2 generates nothing and is pure retrieval. This makes "links-only is a first-class output" concrete — format 2 is a shipped format, not a fallback. Both are also cheap to ground honestly, which matters given provenance is a P0 gate: format 2 sidesteps hallucination entirely, and format 1's citation requirement is the check on it. **Knock-on:** neither format is the worked-example-in-your-own-codebase one, so the S4 pointer-resolution path would get no end-to-end test in v1 — mitigated by letting the user's own code count as a citable source for format 1, rather than by adding a third format.
- **2026-09-16 — Deferred S16 (does re-running rewrite paraphrases the user has already judged), without dropping it.** Not decided yet, but expected to be allowed for eventually. **Two constraints follow.** First, the schema must keep **supersession expressible** even though the policy is undecided — a paraphrase must be supersedable without destroying the original or orphaning the user judgment attached to it. That is free in an append-only log and expensive to retrofit into a mutable one, which is much of why the event log was chosen. Second, **when regeneration lands it runs as a background process** (Freddie): it is an LLM pass over the user's entire history, so it must be asynchronous, interruptible and resumable, with observable progress — and append-only means a partial pass is a shorter log rather than corruption, a property to rely on deliberately.
- **2026-09-16 — v1 regeneration ships the conservative case: encounters carrying a user judgment are left entirely alone.** Only un-judged encounters are re-run. Nothing is rewritten, so no rule is needed — this is the one behaviour that cannot be wrong, and it defers S16 without blocking the skeleton.
- **2026-09-16 — S15: copy transcripts into unrot's own store rather than referencing `~/.claude/projects/` in place.** Rationale (Freddie): do not rely on consistency maintained elsewhere. Claude Code owns the lifecycle of those files — it can rotate them, and the user can clean them up — so a referenced pointer rots silently and S5's "regeneration is a first-class operation" becomes conditional on another tool's retention behaviour. Copying is cheap (~7MB per 14 sessions observed locally). The copy is covered by the same never-syncs rule as the original; per S4 the privacy boundary is the sync line, not the storage, so a local copy adds no new exposure.
- **2026-09-16 — Downgraded the comprehension-check prompt wording from a blocking decision to a low-priority one.** Earlier in this session it was framed as urgent and irreversible. Freddie's call: as long as the question and the answer are both recorded, the grading can be recalculated — and at v1 internal-use scale the wording is unlikely to be right first time anyway, so pick one and iterate. **The requirement that survives:** store the verbatim `prompt_text` on the `explanation_submitted` event, not just an opaque `prompt_version` tag — a version string alone doesn't tell a future re-grader what was asked. Residual risk to revisit before there is a long history or other users: re-grading recovers rubric changes but not signal the prompt never elicited, and "one line, what is it?" tends to elicit *listed*-shaped answers.

## 2026-09-20 — capture (PR-19)

- **2026-09-20 — Confirmed our own transcript parser over an OSS one, with a number behind it (PR-12).** Across the 22 real sessions on this machine there are 1075 `user`-typed lines but only **112 turns a person actually typed**; the rest are `tool_result` blocks, injected `isMeta` system-reminder text, and `isSidechain` subagent traffic. That ~10× gap *is* the detection signal — a parser that treats a `user`-typed line as a human turn hands the detector mostly machinery talking to itself. Existing OSS parsers are built for browsing, cost analysis and search and have no reason to make this distinction, so they don't.
- **2026-09-20 — `thinking` blocks are retained and marked, not discarded.** PR-9 skipped them and the PRD left it open. The raw copy keeps the bytes either way, so the only live question is whether the parsed index surfaces them — and a concept appearing only in Claude's reasoning was arguably never *encountered* by the user, which is a detector's call to make. Retaining with `role='thinking'` lets it decide; discarding decides for it. Images are indexed as a placeholder row with no content, so block counts stay honest.
- **2026-09-20 — Raw material lives in its own database file under `raw/`, not in tables beside the event log.** Makes the S4 sync boundary a **path prefix** rather than a column somebody has to remember to check before uploading. `raw/` carries its own `.gitignore` containing `*` so an accidental `git init` in a parent directory cannot sweep it up.
- **2026-09-20 — Pointers address the transcript's filename stem, not the `sessionId` inside its records.** These disagree: after a compaction the new file's records still carry the *old* session id (1 of 22 sessions locally). The filename is the thing that exists on disk and that our copy is named after. The in-record value is kept separately as `reported_session_id` so the discrepancy stays visible instead of becoming a confusing bug later.
- **2026-09-20 — A rewritten transcript is re-ingested from scratch rather than reconciled.** Ingest stores a hash of the prefix it took; if that stops matching, the stored line numbers are lies, so the parse is dropped and the session re-ingested, with a `rewrites` counter so it is observable. Stitching two different files together would leave pointers silently addressing the wrong lines — the one failure mode that destroys trust in the pointer layer.
- **2026-09-20 — Ingest takes whole lines only.** A live session's final line may be half-written; taking only up to the last newline means a partial write is *not yet ingested* rather than ingested wrong, and the next run picks it up. This is what makes ingesting a running session safe without any locking or coordination with Claude Code.

## 2026-09-20 — detector (PR-20)

- **2026-09-20 — Dropped LangGraph from the shipped detector, keeping LangChain.** The PR-6 spike was a two-node linear graph, which is a function call wearing a state machine. LangChain stays for the OpenAI-compatible client and for the LangSmith tracing the repo already uses; LangGraph bought nothing here and made chunking awkward. PR-26's regeneration wants a plain function it can call in a loop, not a graph it has to drive.
- **2026-09-20 — Only an observed acceptance is a gap.** `questioned` is dropped outright rather than demoted — asking what a term means is evidence of understanding, and therefore a reason to stay quiet. `unclear` (no human turn followed) is kept in the internal ranked list but never emitted: without a next turn there is nothing to have accepted. This is the 2026-09-01 behavioural decision made executable, and it is most of the precision budget.
- **2026-09-20 — The detector treats the model as an untrusted source.** A candidate anchored to a line number with no corresponding window is discarded rather than stored. A pointer that resolves to the wrong place teaches the user the wrong thing and quietly destroys trust in the whole pointer layer, so a missing candidate is strictly the cheaper failure.
- **2026-09-20 — One human reply answers a run of assistant turns, not each turn separately.** Pairing every assistant turn with its own copy of the following human turn repeated that text 9–12× on real sessions, turning 26k characters of assistant text into a 239k-character prompt and forcing 8 model calls where 2 sufficed. Grouping is also the more faithful account of the exchange: the person replied once, to all of it.
- **2026-09-20 — The flag budget is stated to the model, not only enforced afterwards.** It was previously implicit, which made volume depend on how many chunks a session happened to split into — "be sparing" applies per call, so seven calls quietly permitted seven times as many flags as one. Discovered when an efficiency fix reduced a session from seven calls to one and the detector went silent on gaps it had previously found. **Worth remembering as a class of bug:** a per-call instruction plus a per-session budget is a volume control nobody is holding.
- **2026-09-20 — `detector_version` encodes version, model id and a hash of the prompt template.** Editing the prompt therefore changes the recorded provenance of everything produced afterwards, which is what S5 asks for: a silent change in the machine's judgment must not be indistinguishable from a change in the user's world.

## 2026-09-21 — surface (PR-23)

- **2026-09-21 — Chose a JSON API plus a React/Vite SPA over a server-rendered page or a TUI.** The PRD's product shape — "its own UI, its own backend, and potentially a remote server so learning is available on the go" — makes the backend a network boundary whether or not the remote server lands, and a TUI forecloses journeys 10 and 37 (capture and the one-line check away from the dev machine) entirely. The cost is a build step and two dev processes; the return is that the domain heatmap, the timeline and a mobile PWA are later features rather than later rewrites. FastAPI serves `ui/dist` in a built checkout, so *using* the app is still one command.
- **2026-09-21 — The surface names its own empty state; the frontend only renders it.** "An empty gap list is visually distinct from an error state" is a v1 acceptance criterion, and a single blank list cannot say four different things. `GET /api/surface` returns one of `gaps`, `clean`, `cold_start`, `not_captured`, `not_analysed`, each with a headline and a next step. **`failed` is deliberately never sent** — a response saying "I failed" is a response that arrived, so the frontend derives failure from the transport instead.
- **2026-09-21 — Accepted that v1 cannot say "we analysed this session and found nothing."** Nothing records that the detector ran, so a clean session is indistinguishable from an unexamined one. Rather than let `clean` quietly overclaim, the surface reports `not_analysed` until some encounter exists anywhere and `clean` only once everything found has been dealt with. **PR-21 should append a `session_analysed` event**, at which point per-session coverage becomes real. Named here rather than papered over because the whole value of journey 3 is that silence can be trusted.
- **2026-09-21 — Confirm does not close a gap; dismiss does.** Falls directly out of `derive_state`: a dismissal compiles to `known`, a confirmation leaves the concept a `gap` until an explanation grades it `causal`. The UI says "I didn't know this" and "I knew this" rather than confirm/dismiss, because the neutral words invite exactly the wrong guess about which one ends the interaction.
- **2026-09-21 — Presentation policy lives in `api/read.py`, not in the frontend.** Which bucket a concept renders in is a product rule that has to agree with `derive_state`, and putting it in TypeScript would separate the two things that must change together.
- **2026-09-21 — The moment view filters `isMeta` and `isSidechain` rather than merely flagging them.** Caught by looking at the running app: a system-reminder arrives in a `user`-typed line without a person touching the keyboard, and the first build rendered that under a "you" label. Attributing injected text to the user is bad anywhere; in the one view whose job is to show what they actually said, and which they are being asked to judge themselves against, it is disqualifying. This is the PR-19 distinction (1075 `user` lines, 112 human turns) reappearing one layer up.
- **2026-09-21 — Development fixtures stand in for the unbuilt resolver, stamped `origin='fixture'`.** PR-23 is blocked by PR-21 and a UI over an empty log renders nothing. Fixtures go through `events.append` like every other write, so the actor rules and payload validation still apply and no second write path is created. `origin` makes them identifiable in one query and removable in one command, and the surface says on screen when it is showing them — seeded data must never read as a finding about the user. Where capture has run they anchor to **real session ids and line numbers**, so the S4 pointer path is exercised rather than stubbed.
- **2026-09-21 — SQLite connections are opened inside the endpoint body, not injected with `Depends`.** FastAPI dispatches sync dependencies and sync path operations to the threadpool separately and anyio does not promise the same worker thread for both, so a `Depends`-provided connection trips SQLite's same-thread check under uvicorn — while passing every test, because `TestClient` keeps the request on one thread. **Worth remembering as a class of bug:** the test harness was more forgiving than the runtime, so the suite was green and the app was broken. Fixed structurally rather than with `check_same_thread=False`, which works by switching off the check that caught it.

## 2026-09-21 — resolver (PR-21)

- **2026-09-21 — Added `session_analysed`, recorded even when nothing was found.** The zero case is the entire reason the event exists: without it a session the detector examined and found clean is byte-identical to one nobody ever looked at, so the surface could not honestly tell the user that its silence meant anything. Journey 3 asks for silence to be trustworthy; this is what it costs. Closes the gap PR-23 flagged rather than papering over, and `clean` can now say "4 sessions examined, 1 of them with nothing worth flagging" instead of the weaker "nothing is waiting", which is also true of a detector that never ran.
- **2026-09-21 — An exact name or alias match resolves without asking a model at all.** Most re-encounters of a term take this path, and there is no judgment to make, so none is bought. The knock-on is that an alias is not decoration: recording `K8s` against Kubernetes is what stops the same model call being paid for every time that abbreviation reappears.
- **2026-09-21 — The resolver prefers `new` when unsure, and the prompt says why.** The two errors are not symmetric. A duplicate concept is tidied by a later merge; a wrong match files an encounter under something the user never met, and the card looks identical to every real one, so nothing downstream will ever show them it happened. The same asymmetry is enforced in code, not just requested in the prompt — a decision naming a concept id that does not exist is downgraded to `new` rather than honoured, which is the detector's "treat the model as an untrusted source" rule applied one layer up.
- **2026-09-21 — The prompt names the trap explicitly: things in the same space are not the same thing.** Optimistic and pessimistic locking share a domain, a vocabulary and almost every word, and are opposites. §11 already established that similarity cannot distinguish *same as* from *opposite of in the same space*; a model asked to judge sameness inherits that failure unless it is told, so it is told.
- **2026-09-21 — Shipped a no-model decider as a real mode, not a stub.** With no API key the resolver still runs and answers `new` for everything the string matcher missed. That keeps the product usable offline and makes every rule testable without a network, and it is the correct degradation — the alternative, guessing at matches without a model, fails in the direction that cannot be noticed. The CLI says on stderr which decider is running, because silently downgrading would leave the user watching concepts fail to merge with no way to know why.
- **2026-09-21 — Transcript encounters get a content-derived id; manual ones get a fresh one.** A transcript encounter is identified by *where it happened*, so re-running the detector over a session updates that encounter instead of adding a second beside it — which is what makes PR-26's regeneration affordable rather than a source of ever-growing repeat flags. Manual submissions deliberately do the opposite: typing the same term twice means you met it twice, and collapsing those would erase the repetition signal S1 exists to preserve.
- **2026-09-21 — `ModelConfig` moved to `unrot.model`, shared by the detector and the resolver.** The resolver does not depend on detection — it also serves manual submissions, which never touch a transcript — so importing its configuration from `unrot.detector` would assert a relationship that is not there.
- **2026-09-21 — One answer settles a concept, not one encounter.** Found by running the real chain: `idempotency` had two encounters, and confirming one left the card sitting in "Waiting on you" looking untouched — a button that appeared to do nothing. The question being asked is "do you know idempotency?", so a concept met in three sessions asks once. The other encounters stay unjudged in the data, honestly, because we never asked about them. **Re-asking belongs to journey 8's spaced-retrieval loop and must be driven by elapsed time, not by how many times a card happens to be on screen** — which is also why the unjudged encounters are retained rather than back-filled.
